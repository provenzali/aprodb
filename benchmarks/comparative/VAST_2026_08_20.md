# Vast.ai cloud validation, 2026-08-20

AProDB is still a public beta. These results are validation evidence from one disposable Vast.ai host, not a product SLA and not a general claim of superiority.

## Environment

- Provider: Vast.ai disposable SSH instance.
- GPU: NVIDIA Tesla T4, 16 GiB VRAM.
- Kernel: Linux 5.15 x86_64.
- AProDB revision: `ec89d5f` on `release/public-beta-english-validation`.
- Rust: `rustc 1.97.1`.
- Workload: 50,000 deterministic records, 512-byte payload, batches of 500, 50,000 point reads, 20 ordered scans, 3 repetitions.
- Profiles: `compressible` and `random`.
- Supabase live-data import was not completed: the available `palestra` credentials did not provide a working PostgreSQL connection string from the Vast host.

## Correctness gates

All Linux gates passed on the Vast host:

- `cargo fmt --all --check`
- `cargo clippy --workspace --all-targets --no-default-features -- -D warnings`
- `cargo test --workspace --no-default-features`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`

The first MariaDB attempt produced six failures because the benchmark user lacked the `PROCESS` privilege required by the older tablespace-size query. After granting `PROCESS`, all six MariaDB retry runs completed and are the values reported above. The runner was then changed to use ordinary `information_schema.TABLES` metrics so future MariaDB/MySQL runs do not need `PROCESS` just to measure table size.

## GPU compute
